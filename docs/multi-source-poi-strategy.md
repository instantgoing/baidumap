# 多源 POI 清洗、核验与许可策略

策略版本：`poi-provenance-v1`
参数版本：`competition-evidence-v1`
更新日期：2026-09-14

## 1. 数据源角色

| 来源 | 角色 | 可信/核验用途 | 保存与许可边界 |
| --- | --- | --- | --- |
| 百度 Place Search | 运行时主候选源 | 在线检索、UID、名称、位置、类别 | 受百度条款约束；不作为独立真值，不以 Apache-2.0 重新发布原始数据 |
| 政府公开名录 | 独立核验源 | 机构存在、法定名称、地址、类别 | 逐项记录页面、发布时间和原许可；无明确再许可时只保存必要核验字段/引用 |
| 机构官方页面 | 独立核验源 | 名称、入口、服务类型、营业信息 | 保存 URL、访问时间和必要摘录索引，不复制受版权保护页面全文 |
| 官方电话记录 | 独立核验源 | 营业状态、入口或服务确认 | 保存核验记录编号、日期和核验角色，不发布私人电话号码或录音 |
| 实地记录 | 独立核验源 | 入口偏移、同址多名、营业状态 | 记录采集者、时间、位置和授权；公开前处理人脸、车牌等隐私 |
| 固定快照 | 仅离线演示 | 无网可复现 UI 与流程 | 必须标记 `sample-snapshot`；不进入真实准确率计算 |

第三方地图服务不是本项目 Apache-2.0 许可证覆盖的数据集。代码可以按 Apache-2.0 开源，第三方数据仍受各自条款约束。

## 2. 审计数据字典

每条来源记录至少保留：

| 字段 | 含义 |
| --- | --- |
| `sourceRecordId` / `sourceType` | 来源内唯一编号与来源类型 |
| `name` / `address` / `location` | 原来源名称、地址与 BD-09 坐标 |
| `rawCategory` / `category` / `categoryMappingRule` | 原类别、标准类别和映射规则 |
| `baiduUid` | 仅百度记录可有；不是跨来源真值 ID |
| `operatingStatus` | 来源声明的营业状态，不跨来源静默覆盖 |
| `capturedAt` | 该来源的采集/访问时间 |
| `licenseBoundary` / `redistributionAllowed` | 许可说明与能否再分发 |
| `normalizedName` / `normalizedAddress` | 确定性标准化结果 |
| `matchMethods` / `conflicts` | 合并依据与未解决冲突 |

合并结果中 `canonical.selectedFrom` 明确指出展示值来源；`sourceRecords` 保留各来源原值；`conflicts[].resolution` 固定为 `manual-review-required`，因此来源冲突不会被最后写入者覆盖。

## 3. 确定性清洗流程

1. 名称先做 Unicode NFKC、大小写归一、空白/标点清理，再删除有限的行政区前缀和“旗舰店/分店/门店”后缀。连锁分店只有同时满足空间条件才会合并。
2. 地址做 NFKC、标点清理和少量确定性道路词归一；不使用地址文本单独强制合并。
3. 类别先识别项目标准 key，再查版本化别名；无法映射则标为 `other` + `unmapped-review`，不猜类别。
4. 同一百度 UID 自动去重；跨来源优先使用“标准化名称 + 50 米”自动匹配。
5. 同址且名称相似度达到 0.86、距离不超过 50 米时可匹配；50–80 米的相似名称只进入入口偏移人工复核，不自动合并。
6. 同名但超过 80 米保留为不同设施，并记录 `same_name_different_address`。
7. 合并后名称、地址、类别或营业状态出现多值时生成显式 conflict。运行时展示值按“百度主源优先”的规则选取，但该选择不是对独立真值的裁决。

阈值全部位于 `config/evidence-parameters.v1.json`，测试使用固定 `generated_at`，相同输入会得到相同聚类、匹配依据和冲突结果。

## 4. 典型可测试案例

| 案例 | 期望 |
| --- | --- |
| 同 UID 重复返回 | 合并为一个 cluster，保留两条来源记录和 `baidu_uid` 依据 |
| 百度误分类、政府名录给出另一类别 | 保留百度运行时展示值，同时生成 `category_conflict` 等待人工裁决 |
| 同名不同址 | 不合并，进入 `same_name_different_address` 审计项 |
| 校门/商场入口偏移 50–80 米 | 不自动合并，进入 `entrance_offset_review` |
| 同名且 50 米内的跨来源记录 | 自动匹配，但名称/地址/营业状态差异仍生成 conflict |

自动证据位于 `backend/tests/test_multisource_poi.py`。

## 5. 与真实核验的边界

- 运行时仍只用百度 Place Search 生成候选，不把政府页面或电话记录变成不稳定的实时抓取源。
- 独立来源只用于人工真值和审计；同一百度 POI 的另一次请求不能算独立验证。
- `sample_snapshot` 永远不能进入查全率、分类准确率或灰区准确率/召回率分母。
- 若来源许可禁止再分发，只提交指标、必要审计引用和脱敏说明，不提交原始第三方数据表。
- 任何人工冲突在发布前都要保留裁决人、时间、依据和原值；无法裁决就维持 `reviewRequired=true`。
