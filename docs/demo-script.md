# 3 分钟比赛演示

主流程固定使用 `npm run demo`，页面必须显示“样例数据就绪”或 `sample-snapshot`。这是为演示编制的固定样例，不是刚刚在线计算的真实社区数据；真实在线能力由 `docs/real-community-report.md` 证明，工程数据由 `docs/engineering-evidence.md` 证明。

## 演示前检查

```bash
npm ci
npm run check:submission
npm run demo
```

打开 `http://127.0.0.1:4173`，浏览器缩放 100%，预先打开三个标签页：应用、真实社区报告、工程证据。确认未在屏幕、终端历史或环境变量页面展示任何 AK。

## 问题与价值（0:00–0:25）

画面：应用“生活圈分析”页，指向固定样例标识和默认中心点。

> 固定一公里圆无法反映河流、封闭道路、小区入口和绕行。邻里半径用真实步行路网计算 15 分钟边界，再检查菜市场、药店、小学三类基础设施的 1 公里服务盲区。主演示是明确标注的固定样例，保证断网可复现；在线证据单独审计。

动作：用一句话指出支持地址、BD-09 坐标和地图点击三种选点；保留默认 15 分钟并点击“分析 15 分钟生活圈”。

## 真实路网等时圈（0:25–1:05）

画面：四阶段进度、等时圈边界与耗时热力。

> 系统沿 36 个方向分档采样，把最多 50 个终点合并进 Walking RouteMatrix，再围绕 900 秒边界迭代收敛。障碍方向会缩短，局部缺失可插值但会降低置信度；全部方向失败则拒绝伪造边界。

动作：开关一次“耗时热力”，指向“边界复核 12/12”和置信度。必须说“这是样例中的内部交叉复核”；真实报告中 2026-09-13 的同源 RouteMatrix 复核范围是 845–913 秒，也不是独立人工真值。

## 三类设施盲区（1:05–1:40）

画面：分类 POI、服务灰区、三类覆盖卡片。

> Place Search 候选经过类别词典、UID 和名称空间去重，再按生活圈筛选。灰区按独立的一公里设施服务口径计算，不把“15 分钟边界”和“1 公里服务半径”混成一个指标。

动作：点击一个 `G` 灰区，读出缺失类别、连续网格数、面积和边界候选数；指出颜色之外还有形状、纹理、编号和文字。固定样例的 18 个 POI、3 个灰区只用于演示，不进入真实准确率。

## 真实验证（1:40–2:15）

画面：切到 `docs/real-community-report.md` 的“独立人工核验指标”。

> 真实在线样本在 2026-09-13 完成了 274 次 RouteMatrix 有效采样、真实 Place Search 和灰区复核，数据时间、请求 ID、来源与限制均保留。但 30 条独立 POI 真值、独立边界耗时和灰区分层真值尚未人工采集，所以查全率、分类准确率、边界误差、灰区准确率和召回率现在明确写为“不可计算”。仓库已提供三类各 10 条的模板、严格校验器和可重算脚本；缺真值就不报漂亮数字。

动作：快速指向样本量为 0 的待采集表和计算命令。若赛前已由团队完成真值，只能展示由脚本生成且通过校验的新 JSON/报告，并同时展示至少一个真实误差案例；否则保持本段原话。

## 工程优化与容错（2:15–2:42）

画面：切到 `docs/engineering-evidence.md`。

> 基准保留 5 轮全部结果。36 个终点的离线模拟中，批量冷启动把上游调用从 36 次降到 1 次，减少 97.22%；这个数字只证明调用形态，不冒充百度线上延迟。缓存命中配额增量为 0。无 POI、429、5xx、超时、部分方向失败、无路线和无效 AK 都有故障注入；有限重试、QPS、熔断、插值和页面错误状态都有断言。

动作：指向 `offline-simulated` 标签、五轮范围和故障矩阵。补一句：在线失败不会自动偷换样例；能继续半径分析时页面标 `degraded`，不能继续时保持 `error`。

## 开源收尾（2:42–3:00）

画面：README 交付导航或仓库根目录。

> 项目提供 Apache-2.0 代码许可、第三方许可清单、Docker、前后端测试、桌面与移动 E2E、CI 和一键离线演示。百度数据不被重新授权，服务端 AK 只由 FastAPI 运行环境读取。P5 目前展示的是可审计的确定性情景和模板化摘要，不是正式选址；没有真值或授权的内容都列在待办中。

收尾句：

> 邻里半径把“走得到、缺什么、证据可靠吗”放进一条可复现、可审计、断网也能演示的开源流程。

## 现场备用方案

| 故障 | 切换动作 | 证据边界 |
| --- | --- | --- |
| 断网 | 继续当前 `npm run demo`；它已强制 `VITE_DATA_MODE=mock` 且清空浏览器 AK | 全程称“固定样例 / sample-snapshot” |
| 无浏览器 AK | 离线底图照常交互；不要现场申请或粘贴 AK | 不宣称百度 JSAPI 底图在线 |
| 无服务端 AK | 不启动在线 FastAPI 流程，直接使用固定样例并展示已归档真实报告 | 不把报告说成现场请求 |
| 现场在线请求超时/429/5xx | 保留页面错误与 request ID；停止在线重试，另开终端显式执行 `npm run demo` | 不允许在线页面自动替换样例后继续称真实 |
| npm registry 不可达但已预构建 | 会前执行 `npm ci && npm run build`；现场用 `python -m http.server 4173 --directory dist` | 构建产物必须来自同一待提交版本 |
| 浏览器或本机服务异常 | 展示 `docs/assets/` 截图和会前录制的三分钟视频，再用报告/JSON回答 | 录屏、截图、版本哈希需在提交元数据中登记 |

会前至少排练 5 次，并在 `docs/submission-metadata.md` 记录录像、最终哈希和人工确认；当前排练次数与录像均为“待填写”，不能提前勾选。

## 常见评委问答

### 1. 为什么不用固定 1 公里圆直接代表 15 分钟？

步行时间受河流、道路连通、围墙和入口影响；15 分钟范围用 RouteMatrix/DirectionLite 的真实路网耗时。1 公里只用于三类设施服务盲区，是另一条明确口径。

### 2. 你们的 12/12 能证明边界准确吗？

不能证明城市总体准确。它是同一百度路线体系里的内部交叉复核，只证明该次系统输出在抽样点闭环。独立边界误差必须由核验模板中的另一证据链计算，目前仍待人工采集。

### 3. 为什么没有展示 POI 查全率和灰区准确率？

因为缺少独立于百度返回的人工真值。项目宁可显示“不可计算”，也不把同源返回自证为真值；模板、来源校验和计算器已经提交，团队补齐后可重复生成。

### 4. 97.22% 优化是真实线上结果吗？

不是。这是五轮离线模拟中 36 次逐点上游调用对 1 次批量调用的配额/形态对比。真实在线脚本已提供，但本轮未在授权 AK 环境运行，因此线上对比保持待办。

### 5. 部分方向失败会怎样？

少量失败可用相邻方向空间插值，但插值比例进入置信度并产生 warning；全部方向失败会拒绝 Polygon。若 POI 半径分析还能完成，页面明确标记 `degraded`，不会显示为完整成功。

### 6. 在线失败为什么不自动切离线样例？

自动切换会混淆真实与样例。在线模式保留错误；只有讲解者显式启动 `npm run demo` 才进入 `sample-snapshot`。

### 7. 多源数据如何避免冲突和许可问题？

百度是运行时主源，政府名录、机构官方记录、电话和实地记录只做独立核验。每条记录保留来源、时间和许可边界；类别、地址、营业状态冲突进入人工复核，第三方地图数据不以 Apache-2.0 重新发布。

### 8. 服务端 AK 会不会泄漏？

服务端 AK 只从 FastAPI 运行环境或 `backend/.env` 读取，不进入 `VITE_` 变量、浏览器包、日志、报告或样例。浏览器 AK 仅用于公开 JSAPI，并使用 Referer 白名单。

### 9. P5 的规划情景是不是正式选址？

不是。当前 P5 根据灰区面积、人口代理值和缺失类别生成确定性优先级，并给出覆盖网格的上限情景与模板化报告摘要；候选位置仍是灰区质心，没有道路、用地、入口、服务半径和独立真值复核，因此不把它包装成正式规划结论。

### 10. 这是 AI 工具赛道，为什么核心判定不用大模型？

空间覆盖是否达标必须可重复、可审计，所以由版本化规则和路网 API 决定。大模型不应替代地理测量或真值；在核心证据完成前也不扩展非评分的生成式功能。
